## My Discord Enterprise UI Instance is Not Accessible

If you can't access your Discord Enterprise UI instance, there could be several causes. While this issue won't occur with Discord Enterprise Cloud (where our team manages the infrastructure), self-hosted instances might encounter configuration problems.

Let's go through the possible cases where your Discord Enterprise UI instance might be inaccessible:

### 1. Insufficient Storage Space

If you've made many deployments and don't have available space on your server, the Discord Enterprise database might enter recovery mode, preventing access to the user interface. Here's a quick solution to clear cache and free up server space:

```bash
docker system prune -a
docker builder prune -a
docker image prune -a
```

### 2. Container Race Condition During Restart

During a restart, a race condition might occur where Discord Enterprise's dependent containers don't start in the correct order. To troubleshoot this:

First, verify the running containers:
```bash
docker ps
```

You should see all three of these containers running:
```bash
2a5b955c32b6  ghcr.io/skygenesisenterprise/discord-enterprise-manager:latest      "docker-entrypoint.s…"   4 days ago     Up 4 days     0.0.0.0:3000->3000/tcp, :::3000->3000/tcp                                                                             discord-enterprise.1.4bkuszk98muz372kw5mvwkw0h
5a989bf52bc6   postgres:16                 "docker-entrypoint.s…"   4 days ago     Up 4 days     5432/tcp                                                                                                              discord-enterprise-postgres.1.9hvjaxrmby7ex2denjtwo0csf
05be01c5612f   traefik:v2.5                "/entrypoint.sh trae…"   4 days ago     Up 4 days     0.0.0.0:80->80/tcp, :::80->80/tcp, 0.0.0.0:443->443/tcp, :::443->443/tcp, 0.0.0.0:8080->8080/tcp, :::8080->8080/tcp   discord-enterprise-traefik.1.2oktabjmfu558x2d2dy6czt8m
```

<Callout type='info'>
  **Note:** If you're running a version older than v0.29.9, you'll also see a `discord-enterprise-redis` container. Redis is no longer used in self-hosted Discord Enterprise since v0.29.9.
</Callout>

If all three containers are running but you still can't access the interface, it's time to debug:

### Debugging Process

#### 1. Check Container Logs
Start by examining the logs of each container:

```bash
docker service logs discord-enterprise # Discord Enterprise UI
docker service logs discord-enterprise-postgres # Postgres
docker logs discord-enterprise-traefik # Traefik
```

#### 2. Common Database Connection Issue

A common case is when the Postgres container starts after the Discord Enterprise container, preventing Discord Enterprise from connecting to the database. You might see logs like this when running `docker service logs discord-enterprise`:

```ts
> discord-enterprise@v0.22.3 start /app
> node -r dotenv/config dist/server.mjs

Default middlewares already exists
Network is already initilized
Main config already exists
Default traefik config already exists
Migration failed [Error: getaddrinfo ENOTFOUND discord-enterprise-postgres] {
  errno: -3008,
  code: 'ENOTFOUND',
  syscall: 'getaddrinfo',
  hostname: 'discord-enterprise-postgres'
}
Setting up cron jobs....
Main Server Error [Error: getaddrinfo ENOTFOUND discord-enterprise-postgres] {
  errno: -3008,
  code: 'ENOTFOUND',
  syscall: 'getaddrinfo',
  hostname: 'discord-enterprise-postgres'
}
```

To fix this, restart the Discord Enterprise service:
```bash
docker service scale discord-enterprise=0
# Then
docker service scale discord-enterprise=1
```

#### 3. Traefik Configuration Issues

If all containers are running but you still can't access the UI, and Discord Enterprise logs show no errors, the Traefik container might have configuration issues.

When running `docker logs discord-enterprise-traefik`, you might see errors like:

```shell
2025-04-07T15:20:18Z ERR Error occurred during watcher callback error="/etc/discord-enterprise/traefik/dynamic/discord-enterprise.yml: field not found, node: passHostHeader" providerName=file
```

First, try restarting Traefik:
```bash
docker restart discord-enterprise-traefik
```

If you still can't access it and the same error persists in the Traefik logs, you'll need to check the Traefik configuration. In this case, the error indicates that the `passHostHeader` field is missing in the configuration.

If you've modified any Traefik configuration for an `application` and added invalid configuration, the logs will point to the error. For example, the error above mentions `field not found, node: passHostHeader`, which means we need to manually modify the configuration files in `/etc/discord-enterprise/traefik`.

Here's an example of an invalid configuration:

```yaml
http:
  routers:
    discord-enterprise-router-app:
      rule: Host(`my-domain.com`)
      service: discord-enterprise-service-app
      entryPoints:
        - web
      middlewares:
        - redirect-to-https
    discord-enterprise-router-app-secure:
      rule: Host(`my-domain.com`)
      service: discord-enterprise-service-app
      entryPoints:
        - websecure
      tls:
        certResolver: letsencrypt
  services:
    discord-enterprise-service-app:
      loadBalancer:
        servers:
          - url: http://discord-enterprise:3000
          - passHostHeader: true
```

The correct configuration should be:

```yaml
http:
  routers:
    discord-enterprise-router-app:
      rule: Host(`my-domain.com`)
      service: discord-enterprise-service-app
      entryPoints:
        - web
      middlewares:
        - redirect-to-https
    discord-enterprise-router-app-secure:
      rule: Host(`my-domain.com`)
      service: discord-enterprise-service-app
      entryPoints:
        - websecure
      tls:
        certResolver: letsencrypt
  services:
    discord-enterprise-service-app:
      loadBalancer:
        servers:
          - url: http://discord-enterprise:3000
        passHostHeader: true
```

After fixing the configuration, restart Traefik:
```bash
docker restart discord-enterprise-traefik
```

You should now be able to access the user interface.


## Recreate discord-enterprise containers

In the case you want to recreate the discord-enterprise services, you can do the following:

<Callout type='warn'>
  **Important:** Before recreating services, make sure you have backups of your data. Recreating services will not delete your volumes, but it's always good to have backups.
</Callout>

### Recreate Postgres Service

Remove and recreate the discord-enterprise-postgres service:

```bash
docker service rm discord-enterprise-postgres

# Create a new discord-enterprise-postgres service with Docker Secrets
docker service create \
  --name discord-enterprise-postgres \
  --constraint 'node.role==manager' \
  --network discord-enterprise-network \
  --env POSTGRES_USER=discord-enterprise \
  --env POSTGRES_DB=discord-enterprise \
  --secret source=discord_enterprisepostgres_password,target=/run/secrets/postgres_password \
  --env POSTGRES_PASSWORD_FILE=/run/secrets/postgres_password \
  --mount type=volume,source=discord-enterprise-postgres,target=/var/lib/postgresql/data \
  postgres:16
```

<Callout type='info'>
  **Note:** Using Docker Secrets is the recommended approach for managing sensitive data like passwords. The secret is encrypted and only available to services that have been granted access to it.
</Callout>


### Recreate Traefik Service

Remove the discord-enterprise-traefik service:

```bash
# If you are using docker standalone traefik
docker rm -f discord-enterprise-traefik

docker run -d \
    --name discord-enterprise-traefik \
    --restart always \
    -v /etc/discord-enterprise/traefik/traefik.yml:/etc/traefik/traefik.yml \
    -v /etc/discord-enterprise/traefik/dynamic:/etc/discord-enterprise/traefik/dynamic \
    -v /var/run/docker.sock:/var/run/docker.sock:ro \
    -p 80:80/tcp \
    -p 443:443/tcp \
    -p 443:443/udp \
    traefik:v3.6.25

docker network connect discord-enterprise-network discord-enterprise-traefik

# If you are using docker service traefik
docker service rm discord-enterprise-traefik

# Create a new discord-enterprise-traefik service
docker service create \
  --name discord-enterprise-traefik \
  --constraint 'node.role==manager' \
  --network discord-enterprise-network \
  --mount type=bind,source=/etc/discord-enterprise/traefik/traefik.yml,target=/etc/traefik/traefik.yml \
  --mount type=bind,source=/etc/discord-enterprise/traefik/dynamic,target=/etc/discord-enterprise/traefik/dynamic \
  --mount type=bind,source=/var/run/docker.sock,target=/var/run/docker.sock \
  --publish mode=host,published=443,target=443 \
  --publish mode=host,published=80,target=80 \
  --publish mode=host,published=443,target=443,protocol=udp \
  traefik:v3.6.25
```

### Recreate Discord Enterprise Service

Remove and recreate the discord-enterprise service:

<Callout type='info'>
  If the `discord_enterpriseauth_secret` secret doesn't exist on your server (installations older than v0.29.3), create it first: `openssl rand -hex 32 | docker secret create discord_enterpriseauth_secret -`
</Callout>

```bash
docker service rm discord-enterprise

# Create the discord-enterprise service
docker service create \
  --name discord-enterprise \
  --replicas 1 \
  --network discord-enterprise-network \
  --mount type=bind,source=/var/run/docker.sock,target=/var/run/docker.sock \
  --mount type=bind,source=/etc/discord-enterprise,target=/etc/discord-enterprise \
  --mount type=volume,source=discord-enterprise,target=/root/.docker \
  --secret source=discord_enterprisepostgres_password,target=/run/secrets/postgres_password \
  --secret source=discord_enterpriseauth_secret,target=/run/secrets/discord_enterpriseauth_secret \
  --publish published=3000,target=3000,mode=host \
  --update-parallelism 1 \
  --update-order stop-first \
  --constraint 'node.role == manager' \
  -e POSTGRES_PASSWORD_FILE=/run/secrets/postgres_password \
  -e BETTER_AUTH_SECRET_FILE=/run/secrets/discord_enterpriseauth_secret \
 ghcr.io/skygenesisenterprise/discord-enterprise-manager:latest
```

**For Proxmox LXC environments**, add the `--endpoint-mode dnsrr` flag to all services:

```bash
docker service create \
  --name discord-enterprise \
  --replicas 1 \
  --network discord-enterprise-network \
  --mount type=bind,source=/var/run/docker.sock,target=/var/run/docker.sock \
  --mount type=bind,source=/etc/discord-enterprise,target=/etc/discord-enterprise \
  --mount type=volume,source=discord-enterprise,target=/root/.docker \
  --secret source=discord_enterprisepostgres_password,target=/run/secrets/postgres_password \
  --secret source=discord_enterpriseauth_secret,target=/run/secrets/discord_enterpriseauth_secret \
  --publish published=3000,target=3000,mode=host \
  --update-parallelism 1 \
  --update-order stop-first \
  --constraint 'node.role == manager' \
  --endpoint-mode dnsrr \
  -e POSTGRES_PASSWORD_FILE=/run/secrets/postgres_password \
  -e BETTER_AUTH_SECRET_FILE=/run/secrets/discord_enterpriseauth_secret \
 ghcr.io/skygenesisenterprise/discord-enterprise-manager:latest
```



### Final Notes

While the specific issues may vary, the general troubleshooting approach remains similar to what we've described above, and is the general way we always follow when correcting a problem related to the discord-enterprise instance not starting.. If you still can't access the user interface:
1. Check that all containers are running properly
2. Review the logs of each container for specific error messages
3. Verify all configuration files
4. Make sure to read the Traefik documentation for detailed configuration options: https://doc.traefik.io/traefik/
